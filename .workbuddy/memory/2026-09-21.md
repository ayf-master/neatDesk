# 2026-09-21 工作日志

## 修复系统托盘图标空白（无 ND 字母）

**问题**：任务栏上的 exe 图标正常（蓝底白字 ND），但通知区域（隐藏图标）里的托盘图标是一片空蓝色方块。

**根因**：
- `src-tauri/src/tray.rs` 的 `make_tray_icon()` 是用 Rust **手写程序化绘制**的 32x32 蓝色渐变圆角方块 —— 只画了底板，从来没画 "ND" 字母。
- 任务栏图标之所以正常，是因为它来自 tauri-build 打进 exe 的 **.ico 资源**（`bundle.icon`），跟托盘图标是两条完全独立的来源。

**修复**：
- 新增 `scripts/gen-tray-icon.py`：Pillow 在 512x512 画布上画「渐变圆角方块 + 白色 Segoe UI Bold "ND"」，再整体 **BOX 面积平均降采样**到 32x32；额外输出 `tray-preview.png`（16/20/24/32/48 多尺寸预览）。
- 小尺寸做了专门设计：方块内边距压到 16/512（托盘要铺满），字母宽度放大到方块宽度的 76%（主图标是 43%），否则 16px 下字母会糊成一团。
- 产物 `src-tauri/icons/tray-32.rgba`（4096 字节裸 RGBA）。
- `tray.rs` 改为 `Image::new(include_bytes!("../icons/tray-32.rgba"), 32, 32)`。
  选裸 RGBA 而非 PNG 的原因：Tauri 的 `Image::from_bytes` 需要开启 `image-png`/`image-ico` 特性（引入 image 解码依赖），而 `Image::new` 只吃裸像素 —— 零新依赖、零解码开销。

**打包**：MSI 4.9MB + 便携版 6.0MB 均已更新。

## 关键知识点
- Tauri 图标有两个独立来源：**exe 资源图标**（tauri-build 从 `bundle.icon` 的 .ico 写入，决定任务栏/资源管理器）vs **运行时图标**（窗口/托盘，代码里显式设置）。一个对一个错很常见。

## 修复「整理失败」（跨盘移动问题）

**现象**：用户把"图片"分类改名 picture、target_path 设为 `D:\picture`（"文档"设为 `D:\document`），点整理一直失败；删掉 D:\picture 仍失败。

**根因**：后端用 `std::fs::rename` 移动文件，而 Windows 上 rename **只能同卷移动**，跨盘（桌面在 C:、目标在 D:）会报 `ERROR_NOT_SAME_DEVICE`（错误码 17）。旧代码还把这个 17 误标成"目标文件已存在（重名冲突）"，掩盖了真正原因。删不删 D:\picture 都失败，因为卡的是跨盘那一步。

**修复（organizer.rs + undo.rs）**：
- 新增 `pub fn move_file(source, dest)`：先 rename，失败且 `raw_os_error()==Some(17)` 时降级为「复制 + 删除源」；源删失败则回滚已复制的目标，避免重复副本。
- undo.rs 的撤销同样改用 `move_file`（否则跨盘整理后撤销也会失败）。
- 目标目录不存在时自动 `create_dir_all`（删了文件夹也能自动恢复），不再直接报错。
- 错误码处理：新增 80=重名冲突，17 改为"跨盘移动失败"（之前错标成重名）。

**打包**：MSI 4.9MB / 便携版 6.0MB 已更新。
**注意点**：分类会建 `target_path/cat_name` 子文件夹 —— 用户 target=`D:\picture` + cat_name=`picture` 会生成 `D:\picture\picture` 双层目录。若想直接进 `D:\picture`，把 target 改成 `D:\` 即可（cat_name 自动当文件夹名）。

## 构建环境坑
- 本机跑 `npm run tauri build` 时，前端 `npm run build` 在 vite 清空 dist 阶段会失败：环境把 Node 的 `fs.rmSync` 包成了"安全删除（移入回收站）"，在 dist 上触发异常。
- 绕过：用原生 `rm -rf dist`（Git Bash）清空后再 build，vite 的 emptyDir 因目录为空不再调用 rmSync，即可通过。
- Tauri 2 的 `tauri` crate 默认特性**不含** `image-png`，所以 `Image::from_bytes` 默认不可用；`Image::new(&[u8], w, h)` 永远可用。
- 缩小时的降采样滤镜选 PIL 的 `Image.BOX`（面积平均），比 LANCZOS 更干净（无振铃）。

## 修复任务栏图标模糊（真正的根因）

**现象**：托盘图标（隐藏区）清晰了，但**任务栏按钮**上的图标很模糊。用户屏幕 2560×1600 @ **150% 缩放**（实测窗口物理 1222×956 = 逻辑 800×600 的 1.53 倍）。

**根因（关键）**：Tauri 在 Windows 上把 `icon.ico` 的**目录第 0 项**当作运行时窗口图标。
- 源码 `tauri-codegen-2.6.2/src/image.rs` 的 `CachedIcon::new_ico` → `let entry = &icon_dir.entries()[0];`，只解码**第一项**做成 `Image`，设为窗口图标（`default_window_icon`）。任务栏按钮用的就是这个运行时窗口图标。
- 旧 `icon.ico` 目录顺序是升序 `16,24,32,48,64,96,128,256`，**第 0 项 = 16×16** → 150% 缩放下任务栏把 16px 放大到 ~36px，必然糊。
- 为什么第 0 项是 16：Pillow 保存 ICO 时 `IcoImagePlugin._save` 里 `for size in sorted(set(sizes))` **强制升序**，永远把最小尺寸排首位。

**修复**：
- 新增 `scripts/gen-app-icons.py`：**自己写 ICO 目录**（`write_ico`，format 0/1/16，PNG 压缩项），**大尺寸在前** → `entries()[0] = 256×256`。
- 同时用托盘同款清晰管线重做整套应用图标（1024 超采样母版 → BOX 降采样）：`icon.ico`、32/128/128@2x/512/1024 PNG、`icon-512-maskable.png`（铺满无圆角）、`app-icon.png`、`icon-preview.png`。
- 设计参数：INSET_RATIO=0.10、RADIUS_RATIO=0.225、TEXT_WIDTH_RATIO=0.66、LETTER_SPACING=-0.03。

**验证手法**：重建后在新 exe 里 `.find()` 新图标 **256 图层的原始 RGBA 字节段**（选方块内部有颜色的 512 字节，避免匹配到全透明零字节）——唯一命中偏移 5009008，证明内嵌的运行时窗口图标已是 256，不再走 16。

## 关键知识点（补充）
- ICO 目录**顺序有意义**：Tauri 运行时窗口图标只取 `entries()[0]`；Windows 资源管理器则扫描整个尺寸梯取最佳。所以 ICO 要「大尺寸在前」。
- Pillow 存 ICO 会升序排序，想控制顺序必须自己拼 ICONDIR/ICONDIRENTRY（16 字节/项；宽高字节为 0 表示 256）。
- 单例锁：app 已运行时，新版 exe 启动会直接退出（只唤起旧实例）。换 exe 前必须先关旧进程；该 app 关闭按钮是「隐藏到托盘」，`taskkill /F` 或托盘「退出」才能真退出。

## 白屏/打不开的真正根因（重大，结论）
**现象**：窗口能开、标题栏正常，但内容区纯白/纯黑，无 UI。

**根因**：`src-tauri/Cargo.toml` **缺少 `[features] custom-protocol`**。
- `tauri/build.rs:256`：`let custom_protocol = has_feature("custom-protocol"); let dev = !custom_protocol;`
- 缺该 feature → `dev=true` → 走 `devUrl(http://localhost:1420)`（dev 服务器没起）而非内嵌资源 → ERR_CONNECTION_REFUSED 错误页；若同时 GPU 进程崩则表现为纯白/纯黑。

**修复**：Cargo.toml 加 `[features]` `custom-protocol = ["tauri/custom-protocol"]`，用 `cargo build --release --features custom-protocol`（或 `npm run tauri build`）构建。修复后 UI 完整渲染（侧边栏+首页卡片+分布图+立即整理）。**portable/NeatDesk.exe 已用修复版覆盖。**

**本机次要问题**：WebView2 GPU 进程反复崩 → Chromium `FATAL: gpu_data_manager_impl_private.cc:436 GPU process isn't usable. Goodbye.` → 浏览器自杀 → 白屏。诱因：第三方 DLL 注入 `msedgewebview2.exe`（`tsbx.dll`=WorkBuddy agent 沙箱、`qingnse64.dll`/`kbaseconfig64.dll`=WPS）。规避：窗口配置加 `additionalBrowserArgs: "--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --disable-gpu"`（字段见 tauri-utils config.rs:2083）。**从 agent 启动会被注入 tsbx → 崩；用 `explorer.exe "<exe>"` 启动（父进程=用户 shell）则不注入、不崩**，用户日常双击本无此问题。

**可复用排查手法**：
- 崩溃转储：`%LOCALAPPDATA%\<identifier>\EBWebView\Crashpad\reports\*.dmp`；`pip install minidump` → `MinidumpFile.parse()` 看 exception/modules；正则 `[\x20-\x7e]{8,}` 挖 `FATAL:`/`Check failed` 字符串。
- WebView2 进程树 `Get-CimInstance Win32_Process -Filter "Name='msedgewebview2.exe'"`；健康应含 crashpad/gpu/network/renderer/storage，且父进程=app pid。
- 读 webview 真实 URL/状态：Rust `win.url()` / `.eval_with_callback()` 写文件（调试后删）。
- 不受遮挡抓窗口：`PrintWindow(hwnd,hdc,PW_RENDERFULLCONTENT=2)`（DComp 内容有时抓成黑/白，需交叉验证）。
- `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 环境变量对 wry 无效（wry 用 additional_browser_args 覆盖）。
